# Two Pointers

## 1. Ментальная модель

`Two pointers` - это паттерн, где мы держим две важные позиции в данных и двигаем их по правилу.

Указатели могут означать:

- левую и правую границу
- текущий элемент и место записи
- позиции в двух разных строках или массивах
- медленный и быстрый проход по linked list

Главная фича: мы не перебираем все варианты заново, а двигаем указатели так, чтобы уже обработанная часть больше не требовала повторной проверки.

> Указатели двигаются по инварианту: часть данных уже обработана или отброшена, а возможный ответ остается в еще не обработанной области.

## 2. Когда узнавать паттерн

В задаче нужно:

- найти пару элементов по условию
- найти максимум или минимум среди пар
- сравнить элементы с двух концов
- проверить палиндром
- проверить подпоследовательность
- пройти по двум строкам или массивам одновременно
- изменить массив `in-place`
- удалить, сжать или перенести элементы без дополнительного массива
- сохранить относительный порядок элементов
- найти середину или цикл в linked list

Сигналы в условии:

- sorted array / sorted input
- pair / two numbers / target sum
- max pair / min pair
- palindrome
- subsequence
- merge two strings / arrays
- remove duplicates / remove elements
- move zeroes / move elements
- in-place
- preserve relative order
- linked list cycle / middle of linked list

> Если в голову приходит вложенный цикл по парам элементов, стоит проверить, можно ли заменить его двумя указателями.

## 3. Основные формы

`Two pointers` имеет несколько форм. Их стоит определять по роли указателей.

### Left / right

Когда использовать:

- поиск пары в отсортированном массиве
- палиндром
- максимум или минимум среди пар
- выбор двух границ

Инвариант:

> Все кандидаты за пределами `[left, right]` уже проверены или точно не могут улучшить ответ.

Псевдокод:

```text
left := 0
right := len(nums) - 1

for left < right {
    // используем nums[left] и nums[right]

    if нужно_двинуть_left {
        left++
    } else {
        right--
    }
}
```

Примеры: [Container With Most Water](https://leetcode.com/problems/container-with-most-water), [Two Sum II](https://leetcode.com/problems/two-sum-ii-input-array-is-sorted)

### Read / write

Когда использовать:

- изменить массив `in-place`
- удалить элементы
- сжать массив
- перенести элементы в начало или конец
- сохранить относительный порядок

Инвариант:

> Все элементы до `write` уже находятся в правильном состоянии.

Псевдокод:

```text
write := 0

for read := 0; read < len(nums); read++ {
    if nums[read] подходит {
        nums[write] = nums[read]
        write++
    }
}
```

Примеры: [Move Zeroes](https://leetcode.com/problems/move-zeroes), [Remove Duplicates](https://leetcode.com/problems/remove-duplicates-from-sorted-array)

### Two sequences

Когда использовать:

- сравнить две строки или массива
- проверить подпоследовательность
- слить две последовательности
- идти по двум входам одновременно

Инвариант:

> Все элементы до текущих указателей уже сопоставлены, использованы или отброшены по правилу задачи.

Псевдокод:

```text
i := 0
j := 0

for i < len(a) && j < len(b) {
    // сравниваем или сопоставляем a[i] и b[j]

    if условие_для_i {
        i++
    }

    if условие_для_j {
        j++
    }
}
```

Примеры: [Is Subsequence](https://leetcode.com/problems/is-subsequence), [Merge Strings Alternately](https://leetcode.com/problems/merge-strings-alternately)

### Fast / slow

Когда использовать:

- найти середину linked list
- найти цикл
- найти точку встречи

Инвариант:

> `fast` проходит данные быстрее, а положение `slow` отражает нужную точку относительно уже пройденного пути.

Псевдокод:

```text
slow := head
fast := head

for fast != nil && fast.Next != nil {
    slow = slow.Next
    fast = fast.Next.Next
}
```

Примеры: середина linked list, цикл в linked list

Отдельный похожий прием: два указателя с отступом. Например, чтобы найти или удалить `n`-й элемент с конца, сначала создают расстояние `n` между `fast` и `slow`, а потом двигают оба указателя с одинаковой скоростью.

## 4. Как думать на собеседовании

1. Определить роли указателей: `left/right`, `read/write`, `i/j`, `slow/fast`.
2. Сформулировать инвариант: что уже обработано и что еще остается кандидатом.
3. Решить, какой указатель двигать и почему это безопасно.
4. Понять, когда обновлять ответ: до движения, после движения или только при валидном состоянии.
5. Проверить условие цикла: `left < right`, `left <= right`, `i < len(a) && j < len(b)`.
6. Прогнать руками маленький пример: пустой input, один элемент, два элемента, ответ в начале или в конце.

## 5. Частые ловушки

- Не понять роли указателей и двигать их случайно.
- Двигать не тот указатель в отсортированном массиве.
- Обновить ответ не в тот момент.
- Перепутать `left < right` и `left <= right`.
- Забыть обработать остаток второй последовательности после merge.
- Потерять относительный порядок при `in-place` изменениях.
- Сделать бесконечный цикл: внутри цикла хотя бы один указатель должен двигаться.
- Обратиться к `nums[0]`, `right := len(nums)-1` или `head.Next` без проверки пустого input.
- В linked list изменить `cur.Next` до сохранения `next`.
- Для fast/slow забыть проверку `fast != nil && fast.Next != nil`.

## 6. Сложность

Обычно:

- Time: `O(n)`
- Space: `O(1)`

Почему:

> Каждый указатель движется только в одну сторону, а каждый элемент обрабатывается не больше одного-двух раз.

Варианты:

- `left/right`: `O(n)` time, `O(1)` space
- `read/write`: `O(n)` time, `O(1)` space
- `two sequences`: `O(n + m)` time, `O(1)` space если только сравниваем
- `fast/slow`: `O(n)` time, `O(1)` space

Если перед two pointers нужна сортировка, итоговая сложность обычно становится `O(n log n)`.

Если строим новую строку или массив, память считается под результат: обычно `O(n)` или `O(n + m)`.

## 7. Задачи

Карточка задачи должна помогать вспомнить не код, а путь к решению:

> условие задачи -> форма паттерна -> роли указателей -> что уже гарантированно правильно -> шаги решения.

### [Move Zeroes](https://leetcode.com/problems/move-zeroes)

Нужно перенести нули в конец `in-place` и сохранить порядок ненулевых элементов.

Почему это похоже на `two pointers`:

- нужно менять массив `in-place`
- нужно сохранить порядок ненулевых элементов
- один указатель может читать элементы, второй - собирать правильную часть

Это форма `read/write`:

- `read` просматривает массив
- `write` показывает место для следующего ненулевого элемента
- уже гарантированно правильно: `nums[:write]` содержит ненулевые элементы из просмотренной части в правильном порядке

Как прийти к решению:

1. Нам не нужно двигать нули вправо.
2. Вместо этого собираем ненулевые элементы слева.
3. Если `nums[read] != 0`, ставим этот элемент в `write`.
4. `write` двигается только после записи ненулевого элемента.
5. `read` двигается всегда.

Что важно запомнить:

> Не надо "двигать нули". Надо собирать ненулевые элементы в начале, тогда нули сами окажутся справа.

Сложность: `O(n)` time, `O(1)` space.

```go
func moveZeroes(nums []int) {
	read, write := 0, 0

	for read < len(nums) {
		if nums[read] != 0 {
			nums[write], nums[read] = nums[read], nums[write]
			write++
		}
		read++
	}
}
```

### [Valid Palindrome](https://leetcode.com/problems/valid-palindrome)

Проверить, что строчка палиндром, проверять надо только цифры и буквы.

Почему это похоже на `two pointers`:

- палиндром удобно проверять с двух концов
- нужно сравнивать левый и правый значимые символы
- не нужно заранее собирать очищенную строку

Это форма `left/right`:

- `left` ищет следующий значимый символ слева
- `right` ищет следующий значимый символ справа
- уже гарантированно правильно: все значимые пары за пределами `[left, right]` уже совпали

Как прийти к решению:

1. Не нужно через отдельный цикл собирать строчку только из цифр и букв.
2. Вместо этого перед проверкой на равенство смотрим, что знак `left` или `right` - цифра или буква.
3. Если проверяемый элемент не цифра и буква, то двигаем указатель и пропускаем попытку.
4. Если есть хотя бы не совпадение `s[left]` и `s[right]` - возвращаем `false`.
5. Если цикл закончился, то это означает что строчка палиндром.

Что важно запомнить:

> Сначала доводим оба указателя до букв/цифр, потом сравниваем символы без учета регистра.

Сложность: `O(n)` time, `O(1)` space.

```go
func isAlphanumeric(c byte) bool {
	return ('a' <= c && c <= 'z') || ('A' <= c && c <= 'Z') || ('0' <= c && c <= '9')
}

func toLower(c byte) byte {
	if 'A' <= c && c <= 'Z' {
		return c + ('a' - 'A')
	}
	return c
}

func isPalindrome(s string) bool {
	left, right := 0, len(s)-1

	for left < right {
		for left < right && !isAlphanumeric(s[left]) {
			left++
		}

		for left < right && !isAlphanumeric(s[right]) {
			right--
		}

		if toLower(s[left]) != toLower(s[right]) {
			return false
		}

		left++
		right--
	}

	return true
}
```

### [Is Subsequence](https://leetcode.com/problems/is-subsequence)

Нужно проверить, встречается ли `source` внутри `target` в том же порядке.

Почему это похоже на `two pointers`:

- нужно проверить порядок символов
- можно идти по двум строкам одновременно
- один указатель ищет следующий нужный символ, второй сканирует большую строку

Это форма `two sequences`:

- `i` показывает следующий нужный символ из `source`
- `j` сканирует `target`
- уже гарантированно правильно: `source[:i]` найден как подпоследовательность внутри `target[:j]`

Как прийти к решению:

1. Нам нужно найти символы `source` внутри `target` по порядку.
2. Поэтому `j` идет по `target` всегда.
3. Если `target[j] == source[i]`, значит нашли очередной нужный символ.
4. После совпадения двигаем `i`.
5. Если в конце `i == len(source)`, все символы `source` были найдены.

Что важно запомнить:

> `j` двигается всегда, `i` двигается только при совпадении.

Сложность: `O(len(target))` time, `O(1)` space.

```go
func isSubsequence(source string, target string) bool {
    i, j := 0, 0

    for i < len(source) && j < len(target) {
        if target[j] == source[i] {
            i++
        }
        j++
    }

    return i == len(source)
}
```

### [Two Sum II](https://leetcode.com/problems/two-sum-ii-input-array-is-sorted)

Нужно найти два числа, которые в сумме дают `target`.

Почему это похоже на `two pointers`:

- нужно найти пару элементов
- массив уже отсортирован
- по текущей сумме можно понять, какую границу двигать

Это форма `left/right`:

- массив уже отсортирован
- `left` стоит на маленьком числе
- `right` стоит на большом числе
- если сумма маленькая, нужно увеличить ее через `left++`
- если сумма большая, нужно уменьшить ее через `right--`

Как прийти к решению:

1. Ставим `left` в начало, `right` в конец.
2. Считаем `numbers[left] + numbers[right]`.
3. Если сумма равна `target`, нашли ответ.
4. Если сумма меньше `target`, двигаем `left`.
5. Если сумма больше `target`, двигаем `right`.

Что важно запомнить:

> В отсортированном массиве можно управлять суммой через границы: если суммы не хватает, добираем ее через `left++`; если сумма слишком большая, уменьшаем ее через `right--`.

Сложность: `O(n)` time, `O(1)` space.

```go
func twoSum(numbers []int, target int) []int {
    left, right := 1, len(numbers)

    for left < right {
        sum := numbers[left-1] + numbers[right-1]

        if sum == target {
            return []int{left, right}
        } else if sum < target {
            left++
        } else {
            right--
        }
    }

    return []int{}
}
```

### [Container With Most Water](https://leetcode.com/problems/container-with-most-water)

Нужно выбрать две границы, которые дают максимальную площадь.

Почему это похоже на `two pointers`:

- нужно выбрать две границы
- полный перебор всех пар был бы `O(n^2)`
- можно начать с максимальной ширины и двигать одну из границ

Это форма `left/right`:

- `left` и `right` задают текущий контейнер
- `area` хранит лучший ответ среди уже рассмотренных пар
- уже гарантированно правильно: если граница отброшена, лучший ответ с ее участием уже не потерян

Как прийти к решению:

1. Начинаем с самой большой ширины: `left = 0`, `right = len(height)-1`.
2. Считаем площадь текущего контейнера.
3. Обновляем лучший ответ.
4. Любое движение уменьшает ширину.
5. Площадь ограничена меньшей стенкой.
6. Поэтому двигаем указатель на меньшей стенке: только так есть шанс найти стенку выше и улучшить ответ.

Что важно запомнить:

> Если двигать большую стенку, ширина уменьшится, а высота контейнера все равно ограничена старой меньшей стенкой.

Сложность: `O(n)` time, `O(1)` space.

```go
func maxArea(height []int) int {
	left, right := 0, len(height)-1

	area := 0

	for left < right {
		newArea := (right - left) * min(height[left], height[right])
		if newArea > area {
			area = newArea
		}

		if height[left] < height[right] {
			left++
		} else {
			right--
		}
	}

	return area
}
```

### [Max Number of K-Sum Pairs](https://leetcode.com/problems/max-number-of-k-sum-pairs)

Нужно найти максимум непересекающихся пар с суммой `k`.

Почему это похоже на `two pointers`:

- нужно искать пары с суммой `k`
- после сортировки можно управлять суммой через левую и правую границу
- каждый элемент можно использовать один раз, поэтому найденную пару можно сразу отбросить

Это форма `left/right`, но сначала нужна сортировка:

- `left` стоит на маленьких значениях
- `right` стоит на больших значениях
- `count` хранит количество уже найденных пар
- уже гарантированно правильно: элементы за пределами `[left, right]` уже использованы или точно не дадут новую пару с суммой `k`

Как прийти к решению:

1. Без сортировки непонятно, какой указатель двигать.
2. Сортируем массив.
3. Если `nums[left] + nums[right] < k`, сумма слишком маленькая, значит нужно увеличить ее через `left++`.
4. Если сумма больше `k`, нужно уменьшить ее через `right--`.
5. Если сумма равна `k`, нашли пару.
6. После найденной пары двигаем оба указателя, потому что каждый элемент можно использовать только один раз.

Что важно запомнить:

> В отсортированном массиве маленькую сумму увеличиваем через `left`, большую уменьшаем через `right`.

Сложность: `O(n log n)` time из-за сортировки, `O(1)` или `O(log n)` space зависит от сортировки.

```go
func maxOperations(nums []int, k int) int {
	sort.Ints(nums)
	left, right := 0, len(nums) - 1
	count := 0

	for left < right {
		if nums[left]+nums[right] == k {
			count++
			left++
			right--
		} else if nums[left]+nums[right] < k {
			left++
		} else {
			right--
		}
	}

	return count
}
```
